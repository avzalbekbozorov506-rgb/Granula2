# Офис Авзала

Страница «Офис Авзала» показывает, как работает команда из трёх субагентов:
- `avzal-investor` — Авзал, аналитик ЗПИФ: ищет и разбирает фонды.
- `revizor` — Вика (девушка), ревизор: проверяет выводы Авзала по первоисточникам.
- `portfolio-manager` — Хомяк (парень), портфельный менеджер: ведёт `portfolio/portfolio.md` и строит план покупок.
- `shariah-checker` — Шариат-контролёр: проверяет фонды и сделки на соответствие шариату (скрининг, не фетва). В офисе пока не нарисован, его строки журнала начинаются с «Шариат:».

Страница: https://claude.ai/artifact/UVrn1dsS79HDp2L9ZmtK2j
Исходник страницы: `office/index.html`. Состояние хранится в базе страницы (инструмент ArtifactData, коллекция `office`):
- `office/status`: `{state, task, step, summary, updatedAt, agent, agents}`.
  - `agents`: `{avzal: {state, step}, vika: {state, step}, khomyak: {state, step}}` — у каждого своё состояние; персонажи ходят по офису по нему.
  - `state`, `step`, `agent` — состояние и шаг того, кто работает сейчас (`agent` одно из `avzal, vika, khomyak`).
  - `state` одно из `idle, search, read, analyze, write, done, error`.
- `office/log`: `{entries: [{t, state, text, who}]}`, `who` одно из `avzal, vika, khomyak`; новые записи в начале, не больше 40.

## Как команда работает вместе
Когда пользователь просит выбрать, купить или докупить фонд, работает цепочка: Авзал → Вика → Хомяк.
1. Авзал делает разбор.
2. Вика получает отчёт Авзала целиком и проверяет его.
3. Хомяк получает отчёт Авзала и вердикт Вики, обновляет портфель и даёт план (сколько паёв, по какой цене, когда).
Если инвестор просит халяльные варианты или спрашивает «это халяль?», подключай Шариат-контролёра: при выборе фондов — после Авзала (отсеять несоответствующие), перед Хомяком.
Если вопрос только про портфель («что у меня», «сколько получаю»), достаточно Хомяка. Если пользователь просит только одного агента, зови его одного.
Пользователю в конце передай итог по-русски: вывод Авзала с поправками Вики и план Хомяка.

## Офис: шаги для каждого агента
1. Перед запуском: в `office/status` поставь агенту state `search`, step, task (вопрос пользователя коротко), `agent`, updatedAt (UTC); остальным агентам оставь их состояние (новая задача: всех сбросить в `idle`). Добавь запись в `office/log` с `who`. Читай документы перед записью и передавай `if_version`.
2. Очисти журнал и запусти Monitor (timeout 30 мин, при истечении перезапусти, пока агенты работают):
   `mkdir -p .office && : > .office/progress.log && tail -n0 -F .office/progress.log`
3. Запусти субагента в фоне (`run_in_background: true`).
4. На каждую строку `время|этап|текст` из Monitor обновляй `agents.<кто>` и верхние `state/step/agent`, добавляй запись в `office/log`. Кто — по началу текста: «Вика:» → vika, «Хомяк:» → khomyak, иначе avzal (префикс в журнал не пиши). Несколько строк сразу пиши одним batch.
5. Когда агент закончил: его state `done` (или `error`), step «Отчёт готов!» / «Проверила!» / «План готов!». Затем запускай следующего в цепочке (шаги 1, 3, 4). После последнего: summary = главный вывод в 1-3 строки, останови Monitor и передай пользователю ответ.
6. Если офис недоступен, не задерживай ответ пользователю: работа агентов важнее анимации.
